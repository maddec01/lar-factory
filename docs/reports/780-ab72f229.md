## Reproduction and change

The first unchanged affected-suite run passed all 21 tests in 17.35 seconds of wall time. Runs 2 and 3 failed the Azure CLI round-trip test at its default 5000 ms deadline, in 23.18 seconds and 24.72 seconds of wall time respectively. The failure was `Error: Test timed out in 5000ms.` at tracker-sync.test.ts:112. This test launches a fake Azure executable repeatedly through the real transport.

Giving that test 30 seconds exposed the same default deadline in the GitHub CLI integration test at line 225. That run passed 20 tests and timed out on the remaining test in 38.92 seconds of wall time. Both external-process integration tests now have explicit 30-second deadlines. All assertions and the other 19 test deadlines remain unchanged. This addresses the observed deadline failures under contention, not the underlying cost of starting CLI processes. Arbitrarily heavier machine load can still exceed the new deadline.

A deadline-only verification run then reproduced a concrete fixture race. Run 6 failed the Azure saved-state assertion because the fake CLI raised `SyntaxError: Unexpected end of JSON input` while parsing azure.json. Each fake invocation rewrote the shared JSON file in place, including GET calls. A concurrent reader could observe the truncated file, and a GET could overwrite newer state from its stale copy.

Both fake CLI scripts now write to a process-specific sibling and rename it over the state file. GET calls no longer save state. The existing fixture owns those files inside its temporary directory, so its existing teardown removes them even when an assertion fails. The GitHub script had the same in-place write and unconditional GET save and receives the same correction. Production code is unchanged. The original CLI integration cases are the regression boundary, including their saved-state and round-trip assertions.

## Coverage review

No tests or assertions were removed or consolidated. The Azure and GitHub CLI cases cover different transport contracts. The in-memory provider cases cover privacy, permissions, chunk corruption, pending local edits, membership retirement, dependency recovery and validation before authenticated reads. The shared-database cases cover distinct checkpoint and outbox races. The stale failure regression checks a newer pending entry and its error state. None of these cases demonstrated behavior-free coverage that justified deletion.

The existing cache handles close and remove their temporary directories in afterEach. Shared database handles close in finally blocks. This change adds no helper or resource. It reuses the integration tests and changes only their deadlines.
