lar-server's Copies are the components the board uses from its design system and the files they import, with
`foundations/theme.css`; its tests import lar-server's localization, so they stay upstream. The T3 and coss Copies
stay until the board's screens move onto lar-server's.

Licences: maddec01/lar-server is lar's own, with no licence file. pingdotgg/t3code is MIT, in `licenses/t3code.txt`. cosscom/ui is AGPL-3.0 except `apps/origin/`
and `apps/ui/`, which its `LICENSING.md` keeps MIT; `licenses/coss.txt` is that MIT licence, from
`apps/origin/LICENSE.md`.

The board writes its own versions of what the Copies import from T3's app:
`src/lib/utils.ts` (`cn`, `isMacPlatform`, `isWindowsPlatform`) and `src/env.ts`
(`isElectron`). coss's toast imports `@/registry/default/lib/utils`, which the build maps to that `cn`, and
`@/registry/default/ui/button`, which it maps to T3's button: the toast uses only `buttonVariants({ size: "xs" })`,
which T3's button exports. `src/styles.css` imports lar-server's `theme.css`, which sets the palette on
`html[data-theme="minimal"]` (each page's `<html>` carries it), and points the T3 tokens that `theme.css` covers at
lar-server's. It keeps the rest of T3's tokens and the styles the T3 Copies' class names need, written by the board
from T3's `apps/web/src/index.css`, and the theme vars and keyframes coss's toast registry entry adds.
