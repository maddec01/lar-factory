# Restart test measurements

Measured on 2026-11-02 in slice/a9f33a1c-restart-tests, starting at commit 1360f8404f39490b0dccf85c79f6609f322529d7. Node v24.22.1. Commands prepend `/opt/homebrew/opt/node@24/bin` to PATH. Raw logs are in `/tmp/restart-evidence` on the implementation machine.

Other agents ran work-records and web tests in separate worktrees during measurement. Another server suite was also visible. The package and affected-suite baselines overlapped, as did the edited package run and repetitions. Load varied, so these measurements do not establish a controlled elapsed-time improvement.

## Changes and coverage

Reuse the existing subprocess clock adapter with an option that accelerates only the 2000 ms local refresh to 100 ms. Other intervals and provider read timing retain their defaults. The schema-upgrade test waits 250 ms instead of 4200 ms after the first blocked read. This removes 3950 ms of fixed waiting. Production code is unchanged. Existing process-group, watchdog, temporary-directory and timer cleanup remain in place.

The failed-start test no longer starts and stops a successful board before starting the board with missing T3. That startup supplied only the imported record. The failing board can import that record itself. Its subsequent real restart still verifies retry and persisted failed and successful intents.

No test or assertion was deleted. All six cases remain, including schema upgrade, closed-board writes, successful and failed starts, older thread names and uncertain recovery. Related tests were inspected; no demonstrated behavior-free test warranted deletion. No shared helper abstraction was added.

## Commands and results

Each timed command uses `/usr/bin/time -p`.

- `pnpm --dir apps/server test`, baseline: exit 1, 246.74 seconds wall, 892 passed and 4 failed. Failures were vocabulary onboarding, item-details kind disagreement, archive retention and uncertain restart recovery. The restart case hit its 30-second deadline.
- `pnpm --dir apps/server exec vp test run test/restart.test.ts`, baseline: exit 0, 74.16 seconds wall, suite duration 73.37 seconds, six passed.
- `pnpm --dir apps/server test`, edited: exit 0, 271.55 seconds wall, suite duration 248.89 seconds, all 896 passed. This run began before the final local-only adapter adjustment and therefore also exercised the broader acceleration. Final affected-suite runs below exercise the local-only option.
- The affected-suite command above ran ten consecutive times with the final implementation. All exited 0, with six tests passing each time. Wall seconds were 117.00, 45.75, 22.54, 22.16, 23.69, 17.66, 20.52, 21.30, 21.14 and 22.14. Slowest suite duration was 110.97 seconds during package concurrency. Per-test durations were not emitted in those runs, so their precise timeout margins are unavailable.
- `pnpm --dir apps/server exec vp test run test/restart.test.ts --reporter=verbose`: exit 0, 22.15 seconds wall. Per-test milliseconds in file order were 1196, 6118, 2792, 3471, 4150 and 3673. Against unchanged deadlines of 20000, 30000, 60000, 60000, 30000 and 30000 ms, the smallest observed margin in this run was 18804 ms. The slowest test was the closed-board write at 6118 ms.
- `pnpm run typecheck`, `pnpm run knip` and `git diff --check`: exit 0 after the final code changes.

An exploratory run that accelerated every interval failed uncertain recovery at 30 seconds under package concurrency. Its wall duration was 140.73 seconds. The narrower adapter avoids adding provider polling load. A superseded repetition loop was terminated explicitly before the final ten-run series.

The reported 27 to 33 seconds is consistent with subprocess startup and fixed waits, but this machine reproduced substantially longer times under concurrency. The change removes known unnecessary work; a stable overall speedup under identical load remains unproven.
