# The board reads T3 through its first-party protocol

[Issue #636](https://github.com/maddec01/lar-factory/issues/636) implements the choice in [decision #686](https://github.com/maddec01/lar-factory/issues/686). The board reads structured execution facts and subscriptions through one version-aware adapter, using its own scoped client session held in the macOS Keychain. The first-party protocol provides a contract for projects, threads, runs, child tasks, worktrees and available PR context; reading T3's internal database for those facts coupled the board to its schema, while CLI and MCP reads do not provide the chosen subscription interface.

This supersedes [ADR 0005](0005-read-item-stats-from-t3s-database.md) for project discovery, thread association, execution timing and transcript-session mapping. First-user-message association remains until the work-record switch. [ADR 0007](0007-count-item-tokens-like-t3s-usage-page.md) still governs transcript counting and pricing, and [ADR 0008](0008-count-subagent-work-outside-its-parents-turns.md) still governs parent overlap and wall time. Protocol observations now supply their execution inputs.

The residual production SQLite read is `CODEX_TURN_SELECTIONS` in `t3-db.ts`. It joins native provider-turn references to run attempts and reads the earliest running `run.updated` event for that attempt's model selection. This preserves unresolved Codex service-tier pricing when later steering changed the projection's current selection. It remains behind the server adapter; no timing, association or transcript-session SQL fallback supplies production inputs. The current stats path still requires the usage database to open, and reports unavailable stats when it cannot.

The adapter retains timestamped observations on failure, distinguishes unsupported versions and rejected credentials from a disconnected source, and reconnects with fresh authenticated subscriptions. Failed observations never establish an empty result or deletion. The board renews its session before expiry and offers server-side reauthorization after failure. CLI starts and worktree creation remain; an uncertain launch uses documented list/show evidence, requires a unique exact first-user-message match to recover a thread, and otherwise retains duplicate protection. [ADR 0033](0033-confirm-a-deleted-thread-through-the-t3-cli.md) still reserves deletion confirmation for the CLI's exact unavailable response.

Azure policy evaluations, PR statuses and reviewer votes remain direct board-owned reads through the existing Azure login because T3 omits that evidence. Readiness details require fresh successful evidence for the current source revision, withdraw recommendations after failed refresh or changed observations, and preserve the provider's factory Status and PR link.

The supported and exercised version is `0.1.6-nightly.20261030.3917`. Real checks covered authenticated discovery, session renewal, thread association, subscriptions and fresh reconnects, plus execution timing mapping. Full-family real transcript pricing, server restart and live renewal rejection remain unexercised. Azure runtime reads remain unexercised because no organization is configured. Controlled fixtures cover unsupported versions, authentication failures, stale observations, calculation parity and Azure readiness failures. Exact source and runtime evidence live in [execution protocol notes](../../apps/server/src/t3/execution-protocol.md) and [Azure evidence notes](../../apps/server/src/azure/azure-readiness-runtime.md).
