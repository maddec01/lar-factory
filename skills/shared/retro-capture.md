# Retro capture

The board owns follow-up selection and creation. Supply all suggestions to
`propose-retro` in the build's Retro stage; save `[]` when there are none.
Each suggestion has `{title,description,repository,kind}`, where kind is `bug`,
`feature` or `improvement` and repository is the onboarded owner of its code,
instructions, CI or tooling. Resolve an unknown destination before proposing.

The desk's **Choose follow-ups** card records picks and makes chosen List
records/tickets under each destination's retro setting and verified Access.
Report pending failures; never retry by creating records/tickets yourself.
Keep the source build **Done** throughout. Picks authorize later shaping,
not implementation. No chat selection or agent-authored approval substitutes
for the board action.
